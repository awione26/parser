# Админ-панель парсера

Laravel 13 / AdminLTE 3 интерфейс для просмотра данных, собранных Python-парсером,
и управления учетными записями администраторов. Панель размещается по адресу `/cp`.

## Возможности

- обзор количества мастеров, телефонов, городов и категорий;
- серверная таблица мастеров с пагинацией, сортировкой и фильтрами;
- карточка мастера: ФИО, телефон, локация, возраст, пол, опыт, фото, категории и
  ссылка на `uslugi.yandex.ru`;
- точный поиск по нормализованному значению `professionals.phone`;
- удаление одного мастера или до 500 отмеченных мастеров с каскадной очисткой связей;
- потоковый экспорт отфильтрованного реестра в Excel `.xlsx`;
- журнал запусков парсера с результатом, причиной ошибки и ресурсом;
- защищённая форма настройки User-Agent, географии, сетевых задержек, тайм-аутов,
  повторов, браузерного сбора телефонов и типов профилей;
- управление категориями парсинга: название, относительные пути рубрик, порядок и
  включение/отключение без удаления исторических связей мастеров;
- раскрытие телефона только главным администраторам с записью в
  `phone_access_logs`;
- создание, изменение и удаление администраторов с защитой последней учетной записи;
- роль `viewer` для просмотра реестра без доступа к телефонам и управлению учетными
  записями.

Таблицы `professionals`, `categories`, `parser_categories`, `professional_categories`,
`professional_category_rubrics`, `professional_identities`, `logs` и `settings`
принадлежат Alembic/Python.
Laravel не создаёт и не изменяет их схему или поля карточек, но администратор может
удалить профиль целиком, просматривать журнал запусков и менять только фиксированный
whitelist из одиннадцати `SCRAPER_*` параметров. Через отдельный раздел категорий
панель также управляет строками `parser_categories` и общими полями соответствующей
`categories`; удаление конфигурации не удаляет саму категорию и накопленные связи.
Настройки применяются при следующем
запуске парсера. Письменное разрешение на сбор контактных данных оформляется отдельно
и не хранится в таблице `settings`.
Связи категорий и рубрик удаляются внешними ключами MySQL. После нового обхода
парсер может снова добавить удалённую карточку.

## Локальная установка

Требуются PHP 8.3+, Composer 2 и уже подготовленная база парсера.

```bash
cd admin
cp .env.example .env
composer install
php artisan key:generate
```

Заполните в `.env` параметры `DB_*` и `PARSER_DB_*`. Для небольшой установки обе
группы могут указывать на MySQL `uslugi`. В production для `PARSER_DB_*` рекомендуется
отдельный пользователь с `SELECT` к данным парсера, включая `logs` и `settings`,
`DELETE` только к `professionals`, а также `INSERT/UPDATE` только к `settings`.
Для раздела категорий этой роли дополнительно нужны `SELECT/INSERT/UPDATE/DELETE` к
`parser_categories` и `SELECT/INSERT/UPDATE` к `categories`.

Телефон хранится в `professionals.phone` открытым текстом; отдельного ключа для показа
телефонов нет. `APP_KEY` Laravel по-прежнему обязателен для секретов и сессий самой
панели, но он не шифрует колонку телефона в MySQL.

Создание таблиц панели и первого администратора:

```bash
php artisan migrate
```

Перед сидированием задайте в `.env` `ADMIN_INITIAL_LOGIN` и пароль длиной не менее
12 символов, затем выполните:

```bash
php artisan db:seed
php artisan serve
```

Стандартных логина и пароля в проекте нет. После входа откройте
`http://127.0.0.1:8000/cp`.

## Docker Compose

Панель интегрирована в корневой `compose.yaml`. После заполнения корневого `.env`:

```bash
docker compose up -d --build mysql admin admin-web
docker compose exec admin php artisan db:seed --force
```

Интерфейс: `http://127.0.0.1:8080/cp`. MySQL и nginx опубликованы только на loopback.
За HTTPS-прокси установите в корневом `.env` `ADMIN_SESSION_SECURE_COOKIE=true` и
корректный `ADMIN_APP_URL`.

Перед стартом панели Compose последовательно выполняет `parser-migrate`,
`admin-migrate` и `db-grants`. Последний шаг создаёт отдельную runtime-роль панели:
она изменяет таблицы авторизации/аудита, читает данные и журнал парсера, имеет
`DELETE` только к `professionals` и `INSERT/UPDATE` только к `settings`.
Также роль может управлять `parser_categories` и редактировать общие данные категорий.
При upgrade старой схемы с Fernet-телефонами до запуска стека перенесите старый ключ в
`LEGACY_PHONE_ENCRYPTION_KEY` корневого `.env`. Его получает только `parser-migrate`;
после успешной миграции `03` удалите значение. Свежей установке этот секрет не нужен.
Подробный безопасный порядок upgrade описан в корневом `README.md`.

Сам сбор запускается из корня только явной CLI-командой:

```bash
docker compose run --rm parser categories
docker compose run --rm parser crawl --category plumbers --max-pages 1
docker compose run --rm parser-phone crawl \
  --category plumbers --collect-phone --no-respect-robots \
  --max-pages 1 --max-profiles 3
```

Последняя команда разрешена только при наличии письменного разрешения Яндекса,
которое явно покрывает отключение robots-проверки и получение контактных данных.

Chromium есть только в `parser-phone`; основной образ парсера остаётся компактным.
Образы содержат код и зависимости, bind mounts исходников не используются. Поэтому
после правок выполните
`docker compose build parser-migrate parser parser-phone admin-migrate db-grants admin admin-web`.

Не используйте `migrate:fresh`, `db:wipe` и аналогичные команды на общей базе: они
могут удалить таблицы, которыми управляет Alembic.

## Проверки

```bash
composer test
composer lint
```

Feature-тесты используют SQLite и искусственные данные; реальных персональных данных
или сетевых запросов к Яндексу в них нет.

## Безопасность

- `phone` не включается в строки основной таблицы и выдается только отдельным
  admin-only действием; content hash также не сериализуется в интерфейс;
- каждое успешное раскрытие телефона журналируется без самого номера;
- вход ограничен пятью попытками в минуту, сессия регенерируется после входа и
  инвалидируется при выходе;
- `/cp` получает `noindex`, `no-store`, anti-frame и referrer headers;
- внешние фото и ссылки проходят allowlist HTTPS-доменов Яндекса;
- телефон является plaintext PII: любой пользователь БД с `SELECT` к
  `professionals` может прочитать его в обход RBAC и журнала панели;
- скачанный Excel-файл также содержит персональные данные и открытые номера: храните,
  передавайте и удаляйте такие выгрузки по тем же правилам, что и резервные копии БД;
- в production используйте HTTPS, минимальные права и сетевой allowlist MySQL, TLS для
  удаленной БД, шифрование диска/volume и резервных копий, контроль дампов и
  установленный срок хранения/удаления персональных данных.
