# Парсер карточек Яндекс Исполнителей

Python-проект извлекает карточки специалистов с `uslugi.yandex.ru`, нормализует поля и
идемпотентно сохраняет их в MySQL. Основной источник — серверный JSON
`<script id="__PRELOADED_STATE__">`; DOM-селекторы используются только для опционального
раскрытия телефона через обычную кнопку «Телефон».

## Какие данные сохраняются

- `full_name` — отображаемое имя профиля (Яндекс может скрыть фамилию; это не всегда полное ФИО);
- нормализованный телефон nullable в `phone` (`VARCHAR(32)`, открытый текст с индексом)
  и источник/результат получения (`phone_status`);
- `city`, `region`, `country`;
- `age` и дата, на которую он рассчитан (`age_as_of`); точная дата рождения не хранится;
- `gender` — только явно опубликованное значение, без угадывания по имени;
- общий `experience_code`/`experience_text` и опыт отдельно по каждой исходной рубрике
  (код `11` отображается как «Более 10 лет»);
- URL фотографии — изображение не копируется;
- канонический URL, ID профиля и ресурс `uslugi.yandex.ru`;
- связи many-to-many с требуемыми категориями.

Каждый запуск `parse-html`, `parse-profile` или `crawl` также регистрируется в таблице
`logs`: сохраняются время начала и завершения, ресурс, итог `success`/`failure` и
причина ошибки. Пока процесс не завершён, `result` остаётся `NULL`, поэтому аварийно
оборванный контейнер не выглядит как успешный запуск. Время хранится в UTC.

Одиннадцать рабочих параметров `SCRAPER_*` хранятся в таблице `settings` и меняются
через защищённый раздел `/cp/settings`. Миграция создаёт полный начальный набор из
значений `.env.example`; сохранённые значения применяются только к новым запускам.
`DATABASE_URL`, учетные данные MySQL и защитные разрешения `YANDEX_*` в эту таблицу не
попадают и по-прежнему задаются только окружением.

Исходный hydration JSON не сохраняется: в нём есть лишние персональные данные, включая
точную дату рождения, адрес и координаты.

## Архитектура Python-пакета

Код разделён по ответственности: `domain` содержит чистые бизнес-сущности,
`application` управляет сценариями, `parsing` только извлекает и нормализует данные,
а `infrastructure` изолирует HTTP, браузер и SQLAlchemy. CLI не содержит логики сбора —
он преобразует аргументы пользователя в вызовы application-сервисов.

```text
src/uslugi_parser/
├── cli/                 # команды и точка входа
├── application/         # crawl/profile use cases, журнал запусков и DTO
├── domain/              # мастер, категория, рубрика, запуск, статистика обхода
├── parsing/             # profile/category state и нормализация полей
├── infrastructure/
│   ├── http/            # загрузка, rate limit, robots.txt
│   ├── browser/         # разрешённое раскрытие телефона
│   └── database/        # SQLAlchemy и repository
├── config/              # настройки приложения и URL базы
├── catalog/             # статический справочник категорий
├── exceptions.py        # общие ошибки границ слоёв
└── __main__.py
```

## Разрешение и ограничения

На 20 августа 2026 года пункты 5.3–5.4
[Условий использования Яндекс Услуг](https://yandex.ru/legal/uslugi_termsofuse/ru/)
ограничивают автоматизированное копирование и использование контактных данных без
предварительного письменного разрешения оператора. Текущий
[`robots.txt`](https://uslugi.yandex.ru/robots.txt) также запрещает `/api/*`, `/search` и
пагинацию категорий для общего user-agent.

Использование письменного разрешения контролирует оператор установки. Парсер не требует
отдельных переменных `YANDEX_OPERATOR_PERMISSION` и `YANDEX_PHONE_PERMISSION`: наличие и
объём разрешения не могут быть достоверно проверены программным флагом.

Парсер по умолчанию соблюдает `robots.txt`, работает с одним запросом за раз и паузой
2–5 секунд. Он не использует прокси-ротацию, приватные API, чужую авторизацию и не решает
CAPTCHA. При CAPTCHA или блокирующем HTTP-ответе сбор останавливается. Отключение robots
допустимо только если письменное разрешение оператора прямо покрывает такой режим.

## Установка

Требуется Python 3.11+ и MySQL 8.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e '.[dev,phone]'
playwright install chromium
cp .env.example .env
```

Для локальной MySQL можно использовать Docker (замените демонстрационные пароли):

```bash
docker compose up -d mysql
alembic upgrade head
```

`compose.yaml` публикует MySQL только на `127.0.0.1`. Значение `DATABASE_URL` можно
оставить пустым: локальный DSN будет безопасно собран из дискретных `MYSQL_*`
переменных. Для внешней БД задайте полный DSN самостоятельно.

### Полный стек в Docker

В проекте есть два варианта образа парсера и два контейнера интерфейса:

- `parser-migrate`/`parser` — компактный Python 3.13 runtime с парсером и Alembic;
- `parser-phone` — отдельный вариант с системным Debian Chromium и Playwright для
  разрешённого раскрытия телефона;
- `admin-migrate` и `db-grants` — одноразовые миграции Laravel и выдача минимальных
  прав runtime-пользователям;
- `admin` + `admin-web` — PHP-FPM Laravel и nginx со статикой AdminLTE.

MySQL хранится в отдельном volume. Скопируйте `.env.example` в `.env`, замените все
пароли, задайте `ADMIN_APP_KEY` и учетные данные первого администратора. Ключ Laravel
можно сгенерировать так:

```bash
php -r "echo 'base64:'.base64_encode(random_bytes(32)).PHP_EOL;"
```

#### Одноразовый upgrade старых зашифрованных телефонов

Если обновляется ранее развернутая база с `phone_ciphertext`, сначала остановите запись
в базу и создайте проверенную зашифрованную резервную копию. Затем перенесите старое
значение `PHONE_ENCRYPTION_KEY` в `LEGACY_PHONE_ENCRYPTION_KEY` корневого `.env` **до
первого запуска миграций** и выполните:

```bash
docker compose run --rm --build parser-migrate
```

Секрет передается только этому одноразовому сервису. Миграция `03` расшифрует и строго
проверит все старые номера, создаст `professionals.phone`, запишет и проверит каждый
номер, а затем удалит `phone_ciphertext`/`phone_hmac`. При отсутствующем/неверном ключе
или невалидном номере upgrade прервется до изменения схемы. После успешного upgrade
проверьте результат и сразу удалите значение `LEGACY_PHONE_ENCRYPTION_KEY` из `.env`.
Для свежей установки оставьте его пустым. Обратное преобразование без ключа невозможно;
для отката используйте созданную перед upgrade резервную копию. Если старые
зашифрованные резервные копии еще хранятся по вашей политике, держите legacy-ключ только
в отдельном хранилище секретов до их удаления, но не возвращайте его в рабочий `.env`.

Собрать и поднять MySQL с админкой:

```bash
docker compose up -d --build mysql admin admin-web
docker compose exec admin php artisan db:seed --force
```

Одноразовые `parser-migrate` и `admin-migrate` применяют обе группы миграций, после
чего `db-grants` создаёт отдельные runtime-роли. `uslugi_parser` может изменять только
таблицы парсера и журнал запусков, а настройки читает без права изменения.
`uslugi_admin` управляет таблицами авторизации и аудитом, может удалить мастера и
изменить только фиксированные строки таблицы `settings`. Парсер является CLI-задачей:
сбор не стартует вместе со стеком и не перезапускается автоматически. Обычные команды
выполняются в компактном образе:

```bash
docker compose run --rm parser categories
docker compose run --rm parser crawl --category plumbers --max-pages 1 --max-profiles 10
```

Только для разрешённого сбора телефона используйте отдельный образ с браузером:

```bash
docker compose run --rm parser-phone crawl \
  --category plumbers --collect-phone --no-respect-robots \
  --max-pages 1 --max-profiles 3
```

Флаг `--no-respect-robots` здесь необходим технически, но допустим только если ваше
письменное разрешение Яндекса прямо покрывает этот режим и получение контактов.

Для безопасной проверки без записи:

```bash
docker compose run --rm parser crawl \
  --category plumbers --max-pages 1 --max-profiles 3 --dry-run
```

Дополнительные permission-флаги для запуска не требуются. Chromium установлен только в
`parser-phone`; он запускается от непривилегированного пользователя с включённым
Chromium sandbox и закреплённым seccomp-профилем Playwright. Раскрытие телефона
по-прежнему выключено по умолчанию и не обходит CAPTCHA, robots.txt или авторизацию.
Админка доступна на `http://127.0.0.1:8080/cp`.

При запуске парсер одним запросом читает известные ему ключи из `settings`; эти
значения имеют приоритет над `SCRAPER_*` из окружения, а явные CLI-флаги конкретного
запуска имеют последний приоритет. Если таблица настроек или база недоступна,
`crawl` и `parse-profile` завершаются до сетевых запросов. Env-fallback сохраняется
только для справочной команды `categories` и локального `parse-html`.

Исходный код запекается в образы, а контейнеры приложения работают с read-only root
filesystem. Постоянно сохраняются только MySQL и `storage` Laravel. После изменения
кода пересоберите образы с `--build`.

## Использование

Посмотреть 11 настроенных логических категорий и реальные seed URL:

```bash
uslugi-parser categories
```

Разобрать один профиль:

```bash
uslugi-parser parse-profile \
  'https://uslugi.yandex.ru/profile/VadimVolkov-2509716'
```

Разобрать профиль и сохранить его в категории ремонта бытовой техники:

```bash
uslugi-parser parse-profile \
  'https://uslugi.yandex.ru/profile/VadimVolkov-2509716' \
  --category appliance_repair --save
```

Запустить ограниченный тестовый проход без записи в БД:

```bash
uslugi-parser crawl \
  --category plumbers \
  --geo 213-moscow \
  --max-pages 1 \
  --max-profiles 3 \
  --dry-run
```

Сбор всех настроенных категорий в MySQL:

```bash
uslugi-parser crawl --category all --geo 213-moscow --max-pages 1
```

`--max-pages 0` означает все доступные страницы, но при
`SCRAPER_RESPECT_ROBOTS=true` запретит переход на текущую пагинацию — это ожидаемое
поведение. `--no-respect-robots` предусмотрен только для случая, когда вы получили
соответствующее письменное разрешение.

### Телефон

В исходной карточке обычно есть лишь внутренний `phoneId`, который **не является
телефоном**. Парсер сначала берёт явно опубликованный номер WhatsApp, а при
`--collect-phone` нажимает публичную кнопку
«Телефон» в Playwright:

```bash
uslugi-parser parse-profile URL --collect-phone --no-respect-robots
uslugi-parser crawl --category plumbers --collect-phone --no-respect-robots \
  --max-profiles 3 --dry-run
```

Раскрытие через интерфейс может учитываться Яндексом как контакт/лид. Включайте его
только если это прямо покрыто вашим разрешением и бизнес-процессом. Пока
`SCRAPER_RESPECT_ROBOTS=true`, UI-раскрытие блокируется, поскольку его текущий внутренний
маршрут запрещён `robots.txt`.

Если номер скрыт или требуется вход, значение остаётся `NULL`, а причина отражается в
`phone_status`. CAPTCHA при массовом проходе немедленно останавливает весь запуск; для
одиночного профиля результат помечается `blocked_captcha`. Для боевой базы ограничьте
доступ к телефону, шифруйте резервные копии и установите срок хранения согласно вашей
правовой основе.

По требованию схемы номер хранится в MySQL в нормализованном **открытом виде** в колонке
`professionals.phone`; ключ приложению не нужен. Это персональные данные: RBAC и журнал
раскрытий в админке не защищают прямой доступ к базе. Ограничьте MySQL-пользователей и
доступ к Docker host, используйте TLS для удаленной БД, шифрование диска/volume и
резервных копий и настройте срок хранения и удаление. `parse-profile` и `--dry-run`
могут вывести собранный телефон в stdout, поэтому не отправляйте такой вывод в общие
логи/CI-артефакты и применяйте редактирование персональных данных.

`LEGACY_PHONE_ENCRYPTION_KEY` не является runtime-настройкой. Он используется только
один раз при upgrade старой Fernet-схемы и должен быть удален после миграции.

## Категории

Ключи: `designers`, `estimators`, `plumbers`, `electricians`, `carpenters`,
`furniture_assemblers`, `finishers`, `appliance_repair`, `window_repair`,
`locks_and_doors`, `low_voltage`.

Для отделочников, бытовой техники и замков/дверей используются объединения нескольких
официальных сервисных рубрик. Сметчики выбираются через семь точных услуг по составлению
смет, ремонт техники — без услуг установки, окна — без балконных работ, а сборка мебели
— без ремонта и разборки. Профиль принимается в категорию только при точном совпадении
`numberId`; все совпавшие рубрики и их собственный опыт сохраняются в
`professional_category_rubrics`. То же правило действует для ручного
`parse-profile --category ... --save`. Географию задаёт slug Яндекса, например
`213-moscow`.

`first_seen_at`/`last_seen_at` фиксируют историю наблюдений. Ограниченный или прерванный
проход намеренно не помечает старые записи удалёнными: безопасная деактивация требует
отдельного полного reconciliation-запуска, которого в этой версии нет. Для среза
актуальности используйте `last_seen_at` и собственный срок давности.

Повторный парсинг выполняет idempotent upsert и не добавляет вторую строку мастера.
База защищает идентичность двумя независимыми уникальными ключами: ID профиля источника
и SHA-256 канонического URL без tracking-параметров. Если эти ключи уже относятся к
двум разным строкам, запись прерывается как конфликт идентичности. ФИО и телефон в
дедупликации не участвуют, поскольку у разных людей могут совпадать имя или общий номер.
Все ранее встреченные варианты ID сохраняются в `professional_identities`, поэтому
последующая смена URL не теряет уже установленную связь с существующей карточкой.
Перед применением миграции `20260827_06` к существующей установке завершите все
запущенные задачи парсинга. Миграция сначала проверяет старые строки и при найденных
дублях останавливается до DDL с номерами конфликтующих записей.

## Проверки

```bash
pytest
ruff check .
```

Юнит-тесты используют synthetic JSON и обезличенные contract fixtures структуры
реального hydration state; к сайту они не обращаются. Локальная repository-проверка
выполняется на SQLite. Workflow CI поднимает MySQL 8.4 и дополнительно проверяет
Alembic, составной FK/cascade, миграцию legacy-телефонов и конкурентный upsert. Локально
тот же тест запускается только на одноразовой базе с именем `*_test`:

```bash
RUN_MYSQL_INTEGRATION=1 \
MYSQL_TEST_DATABASE_URL='mysql+pymysql://user:pass@127.0.0.1/db_test' \
pytest -m mysql
```

## Админ-панель

В каталоге [`admin`](admin/) находится отдельное Laravel 13 / AdminLTE 3 приложение,
созданное на основе
[`janickiy/laravel13_adminpanel`](https://github.com/janickiy/laravel13_adminpanel/tree/69ca06aa94e55cf23e2ca7c28527fee921f9abb9).
Оно подключается к той же MySQL и предоставляет:

- обзор статистики;
- таблицу и карточки мастеров с ФИО, телефоном, локацией, возрастом,
  полом, опытом, фото и ссылкой на источник;
- фильтрацию по категориям и полям карточки;
- одиночное и массовое удаление мастеров для роли `admin`;
- экспорт текущей отфильтрованной выборки в Excel `.xlsx`;
- журнал запусков парсера с результатом, причиной ошибки и ресурсом;
- раздел настройки одиннадцати рабочих параметров парсера;
- безопасное управление администраторами.

Телефон хранится в базе открытым текстом, но интерфейс выдает его только главному
администратору после явного нажатия; каждое раскрытие журналируется без самого номера.
Роль `viewer` видит карточки без телефона и не может управлять учетными записями.

Для запуска админки добавьте в корневой `.env` `ADMIN_APP_KEY`, логин и пароль
первого администратора (не менее 12 символов), затем:

```bash
docker compose up -d --build mysql admin admin-web
docker compose exec admin php artisan db:seed --force
```

Админка будет доступна на `http://127.0.0.1:${ADMIN_HOST_PORT}/cp` (в текущем локальном
`.env` используется порт `8088`). Разделы `/cp/logs` и `/cp/settings` доступны только
роли `admin`. Изменения настроек применяются при следующем запуске CLI; разрешения
`YANDEX_*` из панели намеренно не меняются. Подробная локальная установка, параметры
двух подключений к БД и меры безопасности описаны в
[`admin/README.md`](admin/README.md).
